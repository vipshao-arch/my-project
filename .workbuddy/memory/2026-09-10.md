## 修复：原地攻击后角色偶现朝向跳回待机方向

**问题**：静止（原地）攻击结束后，角色偶现朝向从「攻击方向（鼠标）」跳回「待机方向（摄像机系移动方向）」。

**根因**（`SkillController.cs`）：
- `_postAttackFacingHeld` 标志本意是「攻击完全结束且无移动输入 → 保持攻击后朝向，直到下一次移动输入」。
- 但它是死代码：被赋值发生在 `ExitCombatMode()` **之后**（`UpdateCombatLocomotion` 里），而唯一检查点在 `LateUpdate` 且要求 `_inCombatMode == true`（此时已变 false）→ 永远无法生效。
- 结果：`ExitCombatMode` 无条件 `_motor.lockRotation = false` + `isStrafing = false`。之后玩家一旦移动，`CharacterMotor.FreeMovement` 的 `canRotate = input!=0 && !lockRotation` 成立，用 `GetMoveDirection()`（摄像机相对方向）把角色 `Lerp` 拉回待机朝向。

**修复**（三处，均在 `SkillController.cs`）：
1. `ExitCombatMode()`：把 `_postAttackFacingHeld = enableAttackFacingHold && !HasCurrentMovementInput()` 前移到退出战斗当帧；`lockRotation = _postAttackFacingHeld`（保持期仍锁定，否则恢复）。
2. `UpdateCombatLocomotion()`：删除 `ExitCombatMode()` 之后重复的 `_postAttackFacingHeld = ...` 赋值。
3. `HandleMovementInterrupt()`：移动开始（`isMoving && !_wasMoving`）时，若此前处于保持期（`wasHoldingFacing`）且已退出战斗（`!_inCombatMode`），恢复 `lockRotation = false`，让角色自然转向移动方向。

**设计确认**：战斗状态（含攻击动画+1s 姿态保持窗）角色根≡瞄准（实时朝向鼠标）；攻击后退出战斗的瞬间改为「保持朝向直到重新移动」，不再突兀跳回待机。

**待验证**：原地攻击 → 站住不动 → 观察朝向不跳；攻击后立刻按移动键 → 角色应平滑转入移动方向而非瞬间跳回。

## 修复：移动攻击时根节点不跟随鼠标（朝向错乱/滞后）

**问题**：战斗移动（含移动攻击）状态下，根节点应实时跟随鼠标；但移动攻击期间 `transform.rotation` 无人更新，根冻结在旧朝向，与「物理位移（CombatFacing）」「下半身动画（InputVertical/Horizontal）」脱节。

**根因**（`SkillController.cs` 的 `LateUpdate`）：
- `attackPoseActive = IsBasicAttackPose` 对「静止普攻」和「移动攻击」都为 true。
- 钉住分支要求 `_hasLastAttackFacing`，但移动攻击走 `UnlockAttackFacing()` 置 false → 不钉。
- `ApplyCombatRotation()` 条件里 `!attackPoseActive` 又把移动攻击一起跳过 → 移动攻击期间根彻底不转。

**修复**：
1. 用 `pinnedToAttackFacing = attackPoseActive && _hasLastAttackFacing` 区分「静止普攻钉住」与「移动攻击」；`ApplyCombatRotation` 条件从 `!attackPoseActive` 改为 `!pinnedToAttackFacing`，让移动攻击也实时跟随鼠标。
2. 删除已废弃的「移动攻击上半身偏向」系统（`UpdateMoveAttackAim`、`_smoothAimReturn`、`moveAttackAimMaxAngle/Weight/BlendSpeed`、`combatAimReturnSpeed` 及对应私有字段）——根已直对鼠标，上半身再偏会引入首帧抖动。

**设计定论**：战斗中根≡鼠标（实时），下半身动画 + 物理位移基于「原始输入 + 攻击朝向系」（W 追击 / S 边退边打 / A·D 侧移）。物理/动画/根三者同源同帧。

## 修复：实际位移方向不对（根朝向与物理位移采样时刻不同源）

**问题**：移动中快速甩鼠标，身体已转向新攻击方向，但实际位移（`_rb.velocity`）仍朝旧方向滑行——「身体朝一个方向、人却滑向另一方向」。

**根因**（`SkillController.cs`）：
- 攻击朝向的同步原放在 `Update()`（每渲染帧）写 `_motor.CombatFacing`。
- 而 Unity 的 `FixedUpdate` 可能先于 `Update` 执行：本帧物理步读到的 `CombatFacing` 是**上一渲染帧**写下的值。
- 位移方向（`CharacterMotor.ControlSpeed` 的 Strafe 分支用 `CombatFacing` 构建 fwd/right）永远比根朝向（`LateUpdate` 里 `ApplyCombatRotation`）慢一帧，快速甩鼠标时二者错位。

**修复**：
1. 删除 `Update()` 里的 `SyncCombatFacing()` 调用及旧方法。
2. 新增 `FixedUpdate()`：把「`UpdateTargetDirection()` 算攻击朝向 + 写 `_motor.CombatFacing`」整体移到物理步。
3. 依赖 `[DefaultExecutionOrder(-10)]`：`SkillController.FixedUpdate` 先于 `CharacterMotor.FixedUpdate`（默认 0）执行，本物理步先写好 `CombatFacing`，同一步内 Motor 用最新值算速度；下一 `LateUpdate` 根也读同一 `CombatFacing` → 根与位移严格同源同帧，零相位差。
4. 更新条件与 `UpdateCombatLocomotion` 对齐：`isMoveAttack || !isCasting` 才更新；站立施法（朝向锁定）不改写。
5. 顺手更新 `ApplyCombatRotation()` 顶部注释（「Update 里同步」→「FixedUpdate 里同步」）。

**已知残留（次要）**：`TopdownCameraController._targetYaw/_targetPitch` 在 `LateUpdate`（`UpdateMouseDragRotate`）更新，而 `FixedUpdate` 读它们时是上一渲染帧值 → 仅「右键拖拽旋转摄像机」时攻击朝向慢一帧（约 16ms），远小于已移除的 0.08s 平滑；纯鼠标移动瞄准（主路径）无此滞后。若用户仍反馈拖拽旋转时位移慢，再评估把旋转目标角前移到更早阶段刷新。

**待验证**：① 按住 W 走位、鼠标不动，攻击方向稳定；② 移动中快速甩鼠标，根朝向与实际位移同向一致；③ 越轴 + 八向输入即时切换追击/边退/侧移。

## 修复：持续按住位移键时触发攻击，位移方向应立刻更新

**问题**：持续按住 WASD（尤其攻击前处于**非战斗**状态）触发攻击的瞬间，位移方向先跳向旧方向、下一物理步才跳回攻击朝向——「触发攻击没有立刻更新位移方向」。

**根因**（`SkillController.cs`）：
- `CombatFacing` 只在 `FixedUpdate` 写；而 `FixedUpdate` 有 `!_inCombatMode` 就 return → 非战斗期间 `CombatFacing` 停更、残留旧值（甚至初始 `Vector3.forward`）。
- 攻击起手发生在 `Update`（`HandleInput → TryBasicAttack`）：`EnterCombatMode` 当帧切 `isStrafing=true`，但起手只更新了 `_targetDirection`（`UpdateTargetDirection`/`FaceMouseDirection`），**没写 `CombatFacing`**。
- 于是进入 Strafe 后的第一帧物理步，Motor 拿旧 `CombatFacing` 算位移方向 → 位移方向跳变，下一物理步才被 `FixedUpdate` 修正。

**修复**（两处）：
1. `FaceMouseDirection()`：`transform.rotation = LookRotation(...)` 后同步 `_motor.CombatFacing = _targetDirection`（覆盖静止普攻与技能施法入口）。
2. `TryBasicAttack()` 移动攻击分支：`UpdateTargetDirection()` + `UnlockAttackFacing()` 后同步 `_motor.CombatFacing = _targetDirection`。
- 语义自洽：移动攻击后续仍由 `FixedUpdate` 每物理步实时跟随鼠标；静止攻击 `FixedUpdate` 停更 → `CombatFacing` 保持起手朝向（符合锁定设计）。

**待验证**：非战斗状态按住 W 移动中点击普攻 → 攻击瞬间位移方向应直接基于攻击朝向，不出现「先跳旧方向再跳回」。

## 修复：跨机联网对战连不上（Host 只监听回环地址）

**问题**：局域网两台电脑联机时，客户端连不上房主。

**根因**（`Net/NetworkGameManager.cs` + UnityTransport 1.5.0）：
- `UnityTransport.SetConnectionData(addr, port)` 第三参 `listenAddress` 缺省时，服务器监听地址 `ServerListenAddress = addr`（默认 127.0.0.1）→ Host 只监听回环地址，局域网其他机器连不进来。
- `netstat` 证实：运行中的 Host 监听 `UDP 127.0.0.1:7777` 而非 `0.0.0.0:7777`。
- 叠加 bug：连接面板只改 IP 不触发 `SetConnectionData`（代码仅在端口变化时同步），改了房主 IP 仍连 127.0.0.1。

**修复**（`NetworkGameManager.cs` 三处）：
1. `TryStartHost()`：建房时 `SetConnectionData(addr, candidate, "0.0.0.0")` 显式监听所有网卡。
2. 「加入(Client)」按钮：`StartClient` 前把 GUI 填的 address/port 应用进 transport（解决改 IP 不生效）。
3. 连接面板显示「本机 IP」（`GetLocalIPv4()`），房主可直接告知对方填哪个地址。

**外部前置**：Windows 防火墙需放行 Unity 的 UDP 入站（首次启动 Unity 弹授权框需点允许）；本机 IP 30.29.61.61。

## 新功能：SM_Veh_Road_Hog_01 载具驾驶交互

**需求**：角色在车辆周围按 E 上车，驾驶时只能移动不能攻击，速度=角色冲刺速度，Shift 加速×2。

**用户拍板的三个设计决策**：① 八方向移动（WASD 相对摄像机，与角色一致，车头转向移动方向）；② 再按 E 下车；③ 驾驶时隐藏角色本体。

**实现**（新增两个文件）：
- `Assets/_Game/Scripts/Vehicle/VehicleController.cs`：运行时组件。核心思路——「距离判定 + 快照禁用/恢复」：
  - 用 `Vector3.Distance(player, vehicle) <= interactRadius` 判定可交互，而非 Trigger 碰撞体（免改预制体加 Trigger，也避免角色被禁用后 Trigger 生命周期失效）。
  - 上车：`syncSpeedFromCharacter=true` 时从 `CharacterMotor.freeSprintSpeed`（5m/s）同步基础速度；快照并禁用 `CharacterInputHandler`/`SkillController`/`CharacterMotor`/`CharacterActionHandler`/`CharacterLadderAction`，隐藏 Renderer、禁用 Collider、冻结 Rigidbody；`TopdownCameraController.SetTarget(vehicle)` 切镜头。
  - 驾驶：`FixedUpdate` 里读 `LocalInputSource.Shared.MoveAxesRaw` → 摄像机相对方向，`Kinematic Rigidbody + MovePosition/MoveRotation` 驱动（碰撞不穿墙）；Shift → `boostMultiplier=2`。
  - 下车：车侧方落点、按快照原样恢复角色、`SetTarget(player)` 切回镜头。
- `Assets/_Game/Scripts/Vehicle/Editor/VehicleControllerSetup.cs`：菜单 `Tools/Vehicle/Setup Road Hog Vehicle`，一键把组件挂到预制体（`PrefabUtility.LoadPrefabContents` 安全方式）+ 场景里非预制体实例的独立摆放对象。

**关键 API 依赖**：`CharacterMotor.freeSprintSpeed`(5)、`SkillController.ExitCombatMode()/InCombatMode`(Game.SkillSystem)、`CharacterInputHandler.CancelClickMove()/IsClickMoving`、`TopdownCameraController.SetTarget()`、`LocalInputSource.Shared`(Game.Character)、`CharacterActionHandler`/`CharacterLadderAction`(Game.Character)。

**已知边界**：仅本地单机逻辑，未做联机同步（载具位置/驾驶权）；下车点取车侧方，贴墙时落点可能不佳（后续可加落点探测）。

**待验证**：E 上车→镜头切车、角色隐藏；WASD 八方向移动速度=5、Shift=10；车头转向移动方向；再 E 下车角色在车侧恢复、镜头切回、能正常攻击。

## 迭代：载具改为「坦克式转向 + 射线贴地」

**反馈**：① 车辆没贴着地表跑（悬空/穿地）；② 八方向移动手感不像开车。

**根因**：
- 车辆 Kinematic 刚体 `useGravity=false`，不响应重力也不贴地，上下坡/不平地形会悬空或穿地。
- 旧逻辑「八方向相对摄像机移动」像角色走路，不像开车。

**修复**（`VehicleController.cs`）：
1. **坦克式转向**：`FixedUpdate` 里 `throttle=axes.y`（W 前进/S 后退，沿车头 forward=+Z）、`steer=axes.x`（A 左转/D 右转，`MoveRotation(_rb.rotation * Quaternion.Euler(0, steer*speed*dt, 0))` 原地打方向）；新增 `invertSteerInReverse=true`，倒车时 `dirSign=-1` 反转转向（真实车辆手感）。
2. **射线贴地**：新增 `TryGetGroundY()`，从 `pos + up*groundCheckHeight(3m)` 向下 `RaycastAll`，**排除载具自身碰撞体**（`h.collider.transform == transform || IsChildOf(transform)`，覆盖根物体 MeshCollider×3 + 轮子 SphereCollider×4），取最高命中点 y + `groundOffset`；前进/贴地合并为一次 `MovePosition`。
3. 删除不再使用的 `CameraRelativeDirection` 与 `_mainCamera`。
4. 新增字段：`rotationSpeed`（改语义=转向速度 180°/s）、`invertSteerInReverse`、`groundCheckHeight`、`groundOffset`、`groundLayerMask`（默认 `~0` 全层）。

**关键坑**：车辆根物体 `SM_Veh_Road_Hog_01` 上挂了 3 个 `MeshCollider`（车身），`IsChildOf(transform)` 对根物体自身返回 `false`，必须用 `h.collider.transform == transform || IsChildOf` 才能排除，否则射线命中车身顶部导致贴地高度错误。

**待验证**：W 沿车头前进、S 后退、A/D 原地转向（倒车转向反转）、Shift 加速×2、上下坡/不平地形贴地不悬空穿地。

## 迭代：载具「车轮转动 + 真实转弯（自行车模型）」

**反馈**：① 移动时车轮不转；② 转弯是原地打方向，不像真实车辆，要求「配合前进/后退转弯」。

**根因**：
- 旧逻辑 `A/D` 直接 `MoveRotation` 原地绕 Y 轴打方向（坦克式），与「真实车辆需前进/后退才能转向」不符。
- 从未处理车轮视觉（滚动/转向）。

**修复**（`VehicleController.cs`）：
1. **真实转弯（自行车模型）**：`yawRate = (signedSpeed / wheelbase) * tan(δ)`，δ=当前前轮转向角。前进时右打方向车头右转；倒车时车头反向偏转（车尾甩向转向侧）；静止（throttle=0）不转向。转向角增量 = yawRate*dt 转度后 `MoveRotation`。删除 `rotationSpeed`/`invertSteerInReverse`。
2. **前轮转向角平滑**：`_currentSteerAngle = MoveTowards(current, steer*maxSteerAngle, steerSmoothSpeed*dt)`，松手自动回正。
3. **车轮视觉 `UpdateWheelVisuals`**：滚动角 = signedMoveDistance / radius * Rad2Deg（用每个轮子 `SphereCollider.radius`），累积 `%360` 防漂移；后轮 `localRotation=Euler(roll,0,0)`，前轮 `Euler(0,steer,0)*Euler(roll,0,0)`（先转向再滚动）。
4. **车轮自动解析 `ResolveWheels`**：优先用 Inspector 的 `frontWheels[]/rearWheels[]`，否则按名字查找（含 "wheel" 且后缀 fl/fr=前轮、rl/rr=后轮）；轴距默认按前后轮局部 z 距离自动算（该车 ≈3.28m），也可用 `wheelbase` 字段覆盖。
5. 新增字段：`maxSteerAngle`(35°)、`steerSmoothSpeed`(240°/s)、`turnSharpness`(1)、`wheelbase`(0=auto)、`frontWheels[]`、`rearWheels[]`、`invertWheelSpin`。

**车辆结构备忘**（`SM_Veh_Road_Hog_01.prefab`）：4 个轮子节点是根物体直接子物体，各挂 `MeshFilter+MeshRenderer+SphereCollider`（网格与碰撞体同节点，直接旋转节点即可）；前轮 `fl/fr` 在 +Z（z=1.77，半径 0.39），后轮 `rl/rr` 在 -Z（z=-1.51，半径 0.49）；forward=+Z。

**待验证**：移动时 4 轮滚动、前轮随 A/D 转向；只有 W/S 时才转弯（A/D 单按不原地转）；倒车 + A/D 车尾甩向转向侧；车轮滚动方向若反勾 `invertWheelSpin`。

## 迭代：载具「前后左右多点高度检测 + 车身俯仰/侧倾」

**反馈**：车辆前后左右都要支持高度检测，不平地面/上下坡要适配地表高度，表现出前后左右的高低差异（此前只有中心单点贴地，车身永远水平）。

**根因**（`VehicleController.cs`）：
- 旧 `TryGetGroundY` 只在车辆中心打一根射线，把 y 对齐到地面；朝向仅由 yaw 单独控制，车身始终水平 → 坡上/坑洼地时前后轮悬空或陷地，无俯仰侧倾。

**修复**：
1. **显式 `_yaw` 取代增量 `MoveRotation`**：`_yaw` 在 Awake 用 `transform.eulerAngles.y` 初始化；`FixedUpdate` 里自行车模型只累加 `_yaw += yawDeg`，不再 `_rb.MoveRotation(_rb.rotation * ...)`。便于把「yaw 基础朝向」与「地形俯仰/侧倾」干净地组合。
2. **新增 `_trackWidth`（轮距）**：`ResolveWheels` 里取所有轮子 `|localPosition.x|` 均值 ×2，供左右采样与 roll 计算。
3. **四点采样 `SampleGroundPlane`**（替换 `TryGetGroundY`）：在车辆「前左/前右/后左/后右」四个角（局部偏移 ±halfTrack / ±halfWheelbase，经 `yawRot` 转到世界系）分别 `SampleGroundHeight`（单点向下 RaycastAll，排除自身碰撞体），得到四点地表高度。据此算：
   - `groundY` = 四点平均（中心贴地高度）；
   - `pitchDeg = atan2(frontY - rearY, wheelbase)`（前高后低 → 车头上抬，上坡）；
   - `rollDeg = atan2(rightY - leftY, trackWidth)`（右高左低 → 车右倾）。
   - 缺失采样点（掉坑/悬崖边缘射线打空）用已命中点平均补齐，避免跳变。
4. **最终旋转组合**：`newRot = Quaternion.Euler(0,_yaw,0) * Quaternion.Euler(pitchDeg, 0, rollDeg)`——pitch/roll 在 yaw 之后的本地坐标系应用，即绕本地 X/Z 轴俯仰侧倾；`MovePosition` 与 `MoveRotation` 各调一次。
5. 单点采样抽取为 `SampleGroundHeight`（保留排除自身碰撞体的 `== transform || IsChildOf` 逻辑）。

**关键结论**：`RigidbodyConstraints.FreezeRotation` 不阻止 `MoveRotation`（前几轮 Y 转向已验证），故 pitch/roll 同样能通过 `MoveRotation` 生效，无需改 constraints。

**待验证**：上下坡车身前后俯仰、左右斜坡车身侧倾、坑洼/碎石路面四点贴合；前轮悬空/陷地应消失；配合前进/后退转弯与车轮滚动无回归。

## 修复：载具俯仰方向反了（下坡车头上翘）

**问题**：下坡时车身车头向上翘起（应车头下压）。

**根因**：Unity 左手系，`Quaternion.Euler(+pitch, 0, 0)` 绕 X 轴正角旋转使 forward(+Z) 转向 -Y，即**正 pitch = 车头向下**。原代码 `pitchDeg = atan2(frontY - rearY, wheelbase)`：上坡（frontY>rearY）得正值 → 车头向下（应向上）；下坡（frontY<rearY）得负值 → 车头向上翘（应向下）。符号反了。

**修复**：`pitchDeg = atan2(rearY - frontY, wheelbase)`，令「车头上抬」为正值，与最终旋转 `Quaternion.Euler(0,_yaw,0) * Quaternion.Euler(pitchDeg,0,rollDeg)` 语义自洽。roll 方向经核对无误（`Quaternion.Euler` 绕 Z 轴正角 = right 上抬，与「右高左低 → 车右倾」一致），未改。

## 迭代：载具坡度阻挡（超角度陡坡无法开过去）

**需求**：超过一定角度的陡坡（上坡）应该阻挡，车辆无法开过去。

**实现**（`VehicleController.cs`）：
1. 新增字段 `maxClimbAngle = 35f`（Inspector 可调，Ground Snap 区）。
2. `FixedUpdate` 在移动前新增「坡度阻挡」判定：用 `SampleGroundPlane(_rb.position, Quaternion.Euler(0,_yaw,0), ...)` 采样**当前朝向**下的前后坡度 `curPitchDeg`（正值=上坡）。
   - 前进（throttle>0）且 `curPitchDeg > maxClimbAngle` → blocked（挡上坡）；
   - 倒车（throttle<0）且 `curPitchDeg < -maxClimbAngle` → blocked（挡倒上坡，车尾朝上）；
   - 下坡不阻挡。
3. blocked 时不产生位移、不更新 `_yaw`（自行车模型转向需移动，被挡即不能转向），但第 4 步贴地仍照常采样应用 pitch/roll → 车身停在坡上仍贴合坡度姿态；轮子不滚（`signedMove=0`）。
4. 用 C# discard `out float _` 避免未使用变量警告。

**语义要点**：`SampleGroundPlane` 的前/后采样点已按 `yawRot`（车头朝向）旋转到世界系，故 `curPitchDeg` 天然是「车头前进方向的坡度」，与自行车模型（仅沿车头前后移动）完全对齐，无需额外算移动方向坡度。斜向停坡（横在坡上）的 roll 过大场景未做阻挡（边缘情况，暂不处理）。

**待验证**：车头正对 >35° 陡坡按 W 应被挡、原地不动但仍贴合坡面；倒车遇陡上坡同样被挡；下坡可正常开；角度阈值不符可在 Inspector 调 `maxClimbAngle`。

## 迭代：载具「逐步加速到 2 倍速 + 撞停重新提速」

**需求**：长按位移键行驶时车辆逐步加速到「2 倍速」（不再瞬间满速）；撞停后速度归零，需重新提速。

**实现**（`VehicleController.cs`）：
1. **加速度状态机**（替换「瞬间满速 + Shift×2」）：
   - 新增字段 `maxSpeedMultiplier=2`（最高速度 = driveSpeed × 2）、`acceleration=8`（m/s²，加速率）、`brakeDeceleration=16`（m/s²，松手/刹车减速率）。
   - 删除 `boostKey`（LeftShift）、`boostMultiplier` 及 `GetKey(boostKey)` 逻辑——Shift 瞬时翻倍改成「长按位移键逐步加速到 2 倍速」。
   - `_currentSpeed`（有符号瞬时速度）状态机：目标速度 `targetSpeed = throttle * driveSpeed * maxSpeedMultiplier`（仅当 throttle≠0 且未 blocked/未撞停）；`Mathf.Abs(targetSpeed) > Mathf.Abs(_currentSpeed)` 时用 `acceleration` 加速逼近，否则用 `brakeDeceleration` 减速回 0（松手自然减速）。
2. **撞墙检测**（新增，`FixedUpdate` 第 6 步）：`Kinematic MovePosition` 撞静态墙时实际位移被截断——比较 `intended = newPos-beforePos` 与 `actual = _rb.position-beforePos`（水平分量），`actual.magnitude < intended.magnitude * 0.5` 判定撞墙 → `_currentSpeed=0` + `_collisionStopped=true`。
3. **撞停防抖**：`_collisionStopped` 撞墙后保持停止，直到松手（throttle≈0）或反向输入（`inputDir != _collisionBlockDir`）才解除，避免顶着墙每帧「微加速→被挡→归零」抖动。`_collisionBlockDir` 用**实际运动方向**（`_currentSpeed` 符号，而非输入 throttle，因为减速滑行中撞墙时 throttle 可能为 0）。
4. **陡坡阻挡同样归零**：`blocked` 时 `_currentSpeed=0`（撞停）。
5. 上车 `EnterVehicle` 时重置 `_currentSpeed=0`、`_collisionStopped=false`，避免上次驾驶残留。

**待验证**：① 长按 W 车辆从静止平滑加速到约 10m/s（2 倍速），松手平滑减速；② 加速中途撞墙/撞陡坡 → 速度归零，松手或反向后重新长按才再提速；③ 倒车同样逐步加速到 2 倍速；④ 转弯/车轮滚动无回归。加速度手感不符可调 `acceleration`/`brakeDeceleration`，最高速度不符调 `maxSpeedMultiplier`。

## 载具「卡细小缝隙」——地表侦测算法优化 (2026-09-10)

**根因**：地表侦测用 `RaycastAll` 单点射线采样，采样点落到地面细小缝隙/裂缝时会采到缝底，导致车身被「吞」进缝里被碰撞体夹住卡死，或姿态/高度单帧跳变。

**改动**（`VehicleController.cs`）：
1. `SampleGroundHeight` 由 `RaycastAll` 改为 `Physics.SphereCastAll`，球半径≈轮子半径（`groundSampleRadius`，0=自动取轮子平均半径≈0.44m）。球体跨不过窄缝 → 骑在缝边缘，不落入缝底。返回 `surfaceY = hit.point.y + radius`（球底接触面高度），贴地公式 `newPos.y = groundY + groundOffset` 语义不变。
2. `SampleGroundPlane` 四点结果改「中位数」抗离群：单点比中位数低超过 `groundSampleRadius*2+0.05`（掉坑）用中位数补齐，只压低点不压高点（凸起石头是真实地形）。
3. 贴地高度/姿态加帧率无关指数平滑（`groundHeightSmooth=12`，`t=1-exp(-smooth*dt)`），吸收缝隙边缘单帧跳变。坡度阻挡仍用即时采样、不受平滑影响。

**新增字段**：`groundSampleRadius=0`、`groundHeightSmooth=12`，已同步 prefab 序列化。

**遗留（碰撞体层面，非地表侦测）**：车身是 3 个 Convex MeshCollider（凸包会把车底填平、比视觉大），开进窄过道仍可能被物理碰撞夹住卡死——这是物理行为，需换碰撞体（Box+Capsule 组合或缩小凸包）才能根治，待用户反馈是否仍卡。

## 载具「悬空 / 空中开车」修复 (2026-09-10)

**根因 1（正常开车固定悬空）**：上一轮把 `SampleGroundHeight` 从 RaycastAll 改成 `SphereCastAll` 时，`surfaceY` 误写成 `hit.point.y + radius`。而 SphereCast 的 `hit.point` 是**球心**位置（向下扫球底先触地，球心在地表上方 radius 处），正确应为 `hit.point.y - radius`。写反导致每帧把 groundY 抬高 2×radius（≈0.88m），车身持续悬空。

**根因 2（开到高处/悬崖边后不落地）**：常规采样范围固定 `groundCheckHeight*2`（6m），车身被抬高后地面可能超范围，`SampleGroundPlane` 四点全采不到就 `return false`，贴地跳过、`newPos.y` 保持不变 → 车身悬空且无恢复机制。

**修复**：
1. `surfaceY = h.point.y - radius`（修正符号，消除固定悬空）。
2. `SampleGroundPlane` 四点全采不到时，加「长距离兜底」：`SphereCastAll` 向下 `groundFallbackDistance`（默认 100m）探下方地表并落回，pitch/roll=0；仍采不到（真悬崖下无地面）才返回 false。

**新增字段**：`groundFallbackDistance=100`，已同步 prefab。

**关键知识点（易错）**：Unity `Physics.SphereCast` 的 `hitInfo.point` 是**球心**而非表面接触点，算地面高度要用 `point - radius`（向下扫）或 `point + radius`（向上扫）。

## 载具「常规状态陷地」——SphereCast 高度补偿最终修正 (2026-09-10)

**根因（符号来回反复的终局结论）**：Unity `Physics.SphereCast` 的 `RaycastHit.point` 返回的是「球表面与地面的接触点」（向下扫描即球底触地点），其 y **直接就是地表高度**，无需任何 ±radius。

三次反馈串起来正好验证了这一点：
- 原始 RaycastAll 点采样：`surfaceY = hit.point.y` → 贴地正常（只报「卡细缝」）。
- 第一次改 SphereCast 误写 `hit.point.y + radius` → 抬高 radius → **悬空**（用户报悬空）。
- 上轮改 `hit.point.y - radius` → 降低 radius → **陷地**（用户报陷地）。
- 正确：`surfaceY = hit.point.y`（不加不减）。

**改动**：`SampleGroundHeight` 主采样与 `SampleGroundPlane` 兜底探测两处，均去掉 `- radius`，直接 `surfaceY/sy = h.point.y`；同步修正注释，标明「hit.point 即球底接触点」。

**关键知识点（易错，务必记住）**：SphereCast/CapsuleCast 的 `hit.point` 是「形状表面接触点」而非「形状中心」。向下扫时球底触地，`hit.point.y` = 地表高度；`hit.normal` 也不等于表面法线（是从接触点指向形状中心的方向）。求地面高度直接取 `hit.point.y` 即可，别加别减。

**需求**：① 增加按 Shift 氮气加速；② 地表小石头会把车撞停，需过滤低矮障碍。

**改动**（`VehicleController.cs` + prefab 序列化）：

## 载具「越障抬升不够、仍卡小石头」—— 越障算法根治 (2026-09-10)

**根因（两个 bug 叠加）**：
1. **抬升基准错误**：`stepUpY = 障碍顶 + stepUpClearance`，但 `newPos` 是车 **pivot(车中心)**，不是车底。车 pivot 到最低碰撞点(轮子底)还有 ~0.5~0.6m，抬升后车底仍低于障碍顶，深度重叠被 Kinematic 刚体去穿透卡死。
2. **只抬升一帧**：`stepUpY` 只在 SweepTest 命中那一帧生效，下一帧车回落贴地，与障碍穿透又被卡死。

**修复**（`VehicleController.cs`）：
1. 新增 `_pivotToBottom`：Awake 收集 `GetComponentsInChildren<Collider>` 合并包围盒，算 `pivot.y - bounds.min.y`（pivot 到轮子底距离）。越障目标高度改为 `障碍顶 + _pivotToBottom + stepUpClearance`，确保「车底」真正越过障碍顶。
2. 单帧抬升 → **持续越障状态机**：新增 `_stepUpObstacle`/`_stepUpHeight`。SweepTest 命中低障碍时记录障碍与目标高度；每帧 `newPos.y = max(newPos.y, _stepUpHeight)` 持续抬升；用 `CarOverlapsObstacleXZ` 判断车与障碍的水平 XZ 投影是否还重叠，脱离重叠才清空越障状态回落贴地。高障碍撞停时同时清空越障状态。上车时重置越障状态。

**关键知识点（易错）**：Kinematic 刚体 MovePosition 的 y 是 **pivot**，越障/贴地抬升量都要以「车底(最低碰撞点)越过目标」为准，需补 `pivotToBottom`；且跨越障碍必须「持续抬升直到水平越过」再回落，单帧抬升必然被物理穿透卡死。

## 载具「越障增强」—— 障碍判定语义化 + 越障姿态锁定 (2026-09-10)

**需求**：小石头仍会卡停/碾不过。用户选了「越障增强」方案（而非 Layer 穿透）。

**方案选型分析（已确认现状）**：项目仅 5 个默认 Layer、无自定义层、碰撞矩阵全开；车辆与角色都在 Default 层。Pebbles 碎石无碰撞体(纯装饰)、Rock 系列是非凸 MeshCollider(真挡车)、Rubble/Blob 是凸包。结论：Layer 穿透是二元的、且需给车辆单独建 Layer 否则角色/子弹也穿透，故选「越障增强」为主方案。

**改动**（`VehicleController.cs` + 4 个 prefab）：
1. **字段重命名+语义化**：`obstacleFilterHeight`(障碍总高≤0.35) → `maxStepOverHeight`(车底需抬升高度差≤此值,默认 0.8)。旧语义用 `bounds.size.y`(整块总高)一刀切，会把「大石头的低矮边缘 / 半埋石头」误判为高障碍撞停。
2. **判定逻辑**：撞墙 SweepTest 命中竖直面后，改算 `stepUpRequired = 障碍顶(bounds.max.y) - 车底当前高(rb.y - _pivotToBottom)`，≤ maxStepOverHeight → 越障，否则撞停。
3. **越障期间锁定姿态**：新增 `steppingUp = _stepUpObstacle != null` 分支，跳过地面采样、`newPos.y=_stepUpHeight`、`newRot=yawRot`(保持水平)。否则采样球会命中障碍本身、把障碍顶误当「地面」导致高度/pitch/roll 抖动。
4. **越障结束重置平滑**：`CarOverlapsObstacleXZ` 脱离重叠清除越障状态时，`_groundSmoothInit=false`，回落贴地重新初始化平滑，避免高度跳变。
5. 删除废弃的 `IsLowObstacle` 方法。

**prefab 同步**：4 个 prefab(Road Hog/Tumbler/Reaper/Greaser)的 `obstacleFilterHeight: 0.35` → `maxStepOverHeight: 0.8`。

**关键知识点**：越障「能不能翻」应看「车底需要抬升的高度差」，而非「障碍物总高」；越障抬升期间必须跳过地面采样，否则障碍顶会被误判为地面。

## 收尾：CS0103 obstacleFilterHeight + Demo.unity 场景残留 override 清理 (2026-09-10)

**现象**：Unity 报 `VehicleController.cs(839,50) error CS0103: The name 'obstacleFilterHeight' does not exist`。

**排查结论**：`VehicleController.cs` 源码里已无任何 `obstacleFilterHeight`（上轮已全改名 `maxStepOverHeight`，grep 全 Assets 仅 Demo.unity 场景残留旧字段名）。CS0103 是 Unity 编辑器「旧脚本编译缓存/未重新编译」的残留报错，非源码问题——切回 Unity 触发重新编译（Assets→Refresh / Ctrl+R，必要时先 Clear Console）即消失。

**顺手清理**：`Demo.unity` 场景 `m_Modifications` 里残留的 `propertyPath: obstacleFilterHeight / value: 1.5` 改为 `propertyPath: maxStepOverHeight / value: 0.8`（旧语义「过滤小物件总高 1.5」不适用于新语义「可翻越高度」，改回与 prefab 默认 0.8 一致）。教训：**改字段名时要全局搜一遍，.cs、prefab、.unity 场景 override 三处都要同步**。
